NOTA TÉCNICA

Confidencialidad y no almacenamiento de datos personales

Producto: Client Form Versión: 2026 Autor: Guilhem Normand

1. Resumen ejecutivo

Esta nota responde a la pregunta planteada: «¿Cómo garantiza la aplicación que la información del cliente no queda guardada en ningún sitio?»

La respuesta es estructural: la aplicación actúa como un espejo digital. Los datos que el cliente teclea en su dispositivo se reflejan en tiempo real en la pantalla del asesor, sin pasar por ningún servidor ni base de datos. En cuanto se cierra la sesión, los datos desaparecen.

2. Arquitectura: cómo funciona el espejo

La transmisión de datos se realiza mediante WebRTC (Web Real-Time Communication), una tecnología de conexión directa entre dispositivos estandarizada por el W3C e implementada de forma nativa en todos los navegadores modernos.

Dispositivo cliente Introduce sus datos
⟶
Canal WebRTC P2P Cifrado extremo a extremo
⟶
Pantalla asesor Muestra datos en tiempo real

Ningún servidor intermedio toca los datos personales del cliente. El servidor de señalización solo actúa como "directorio telefónico" para establecer el canal; una vez abierto, desaparece de la ecuación.

3. ¿Qué datos se almacenan y cuáles no?

Dato ¿Se almacena?
Dirección / CP / Ciudad del cliente No — solo en RAM durante la sesión
Teléfono y e-mail del cliente No — transmitido P2P, nunca escrito en disco
Dirección temporal (hotel/Airbnb) No — mismo canal P2P
Código de sesión (6 dígitos) No — expira al cerrar la pestaña
Nombre de la agencia (licencia) Sí — en KV (no es dato personal)
Fecha de expiración de la licencia Sí — en KV (no es dato personal)
IP + fecha aceptación condiciones Sí — en KV (registro legal de activación)

4. Garantías técnicas clave

4.1 Sin base de datos de clientes

Las funciones serverless únicamente acceden a metadatos de licencia. El código fuente ha sido auditado y no contiene ninguna instrucción de escritura de datos personales.

4.2 Cifrado extremo a extremo

WebRTC utiliza DTLS para el plano de datos y SRTP para el canal de mensajes. Ningún nodo intermedio puede leer el contenido.

4.3 Efímero por diseño

El código de sesión se destruye al cerrar la pestaña. No se persiste en cookies ni storage.

4.4 Sin logs en servidor

Las cabeceras HTTP incluyen Cache-Control: no-store, impidiendo almacenamiento en caché. Los Workers no registran el cuerpo de las peticiones P2P.

5. Ciclo de vida de un dato personal

  • ▸ El cliente teclea su e-mail (campo HTML).
  • ▸ Al pulsar enviar, el script empaqueta los datos en memoria RAM.
  • ▸ El objeto se envía mediante API WebRTC cifrada DTLS directamente al asesor.
  • ▸ El asesor recibe el dato y lo muestra en pantalla.
  • ▸ En ningún momento se realiza una llamada HTTP POST a servidores con estos datos.
  • ▸ Al cerrar la pestaña, el objeto desaparece de la RAM. No queda ninguna copia.

6. Conclusión

  • Cumple el principio de minimización del RGPD (Art. 5.1.c).
  • No existe base de datos de clientes. Los datos nunca tocan un servidor.
  • Canal P2P cifrado extremo a extremo por estándar.
  • El almacenamiento persistente (KV) contiene exclusivamente datos de licencia de la agencia.
