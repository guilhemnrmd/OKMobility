7 langues natives

Comment savons-nous que les données ne sont pas stockées sur vos serveurs ?

C'est vérifiable techniquement — pas seulement promis contractuellement. Le code source est auditable : la connexion PeerJS établit un canal WebRTC direct entre deux navigateurs.

Les fonctions Cloudflare n'acceptent aucun paramètre de données personnelles. Le serveur TURN ne fait que relayer des paquets chiffrés — il est techniquement incapable d'en lire le contenu.

Preuve technique disponible sur demande : schéma d'architecture et accès au code source pour audit.

Que se passe-t-il si Cloudflare tombe en panne ?

SLA contractuel de 99,99% — moins de 52 minutes d'inactivité par an.

En cas de panne partielle, la connexion WebRTC bascule sur les serveurs TURN. La procédure classique reste applicable.

Un cache local (localStorage, 30 jours) permet à chaque terminal de fonctionner même si l'API est momentanément inaccessible.

Développeur indépendant — que se passe-t-il s'il arrête ?

Trois niveaux de protection :

  • Code source complet livré avec la licence.
  • Standards ouverts (WebRTC W3C, Cloudflare Workers).
  • Pile technique simple (HTML/CSS/JS vanilla + serverless).

Clause d'escrow du code source sur demande. Contrat de maintenance pluriannuel disponible.

Cette solution est-elle conforme au RGPD ?

Zéro stockage serveur = meilleur argument RGPD possible.

  • Minimisation (Art. 5.1.c).
  • Suppression (Art. 17) : rien à supprimer.
  • Accès (Art. 15) : résumé en temps réel.
  • Rectification (Art. 16) : bouton Modifier avant envoi.

Sous-traitants conformes EU-US Data Privacy Framework.
